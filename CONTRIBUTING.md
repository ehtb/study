# Contributing to Transformer Notebooks

Thank you for your interest in contributing! This project aims to make transformers and language models understandable through clear, executable notebooks.

## How to Contribute

### Reporting Issues

- Check if the issue already exists before creating a new one
- For bugs, include steps to reproduce and your environment (Python version, OS)
- For notebook issues, include the cell number and any error messages

### Suggesting Improvements

- Clarifications to explanations
- Additional visualizations or examples
- Performance optimizations
- Additional notebooks for related concepts

### Pull Requests

1. Fork the repository
2. Create a new branch for your feature (`git checkout -b feature/description`)
3. Make your changes
4. Test that all notebooks run from top to bottom without errors
5. Commit with clear messages describing the change
6. Push to your fork and submit a pull request

### Notebook Guidelines

- **Clarity first**: The goal is understanding, not brevity
- **Self-contained**: Each notebook should run independently
- **Incremental**: Build complexity one step at a time
- **Visual**: Include plots and visualizations where they help understanding
- **Tested**: Run all cells before submitting

### Code Style

- Follow existing notebook structure and commenting style
- Keep code readable over clever
- Add markdown cells to explain non-obvious steps
- Use meaningful variable names

## Questions?

Open an issue labeled "question" and we'll help clarify.
